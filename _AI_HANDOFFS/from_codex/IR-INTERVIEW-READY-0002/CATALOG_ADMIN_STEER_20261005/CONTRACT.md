## Catalog schema and validation

Catalog schema `missionmed.interview-ready.catalog.v1`: `categories`, `products`. Phase1 group is online only. Category id is one of webcam/mic/light/mount/background/power/accessories; name, intro and order are editorial. Unique product IDs survive moving category/tier and archiving. Product stores category, bc/fc/pj tier, primary boolean, alternative when primary false, order, enabled/archived, explicit badge allowlist, editorial, Amazon identifier/destination, image source/rights evidence, manufacturer URL, expert association and optional legacyKey. No automatic marketing badge. Publish requires every enabled category have exactly one enabled/unarchived primary in each of bc/fc/pj. Disabled/archived products remain in admin data. Existing published product IDs cannot disappear from a draft; removal is archive/disable, with explicit UI confirmation. Archiving a primary requires replacement before publish.

Exact keys; max 7 categories/150 products/256KiB command; bounded plain strings/arrays; unique IDs/orders and badges; HTTPS URLs only, no credentials/fragments/nonstandard ports/local/IP hosts; exact 10-character uppercase ASIN. Amazon destination must be EXACT central `https://www.amazon.com/dp/<ASIN>?tag=missionmatch-20` (blank only for no-purchase plans). Query tracking cannot be manually altered. Remote image defaults denied; exact approved source+rights record must pass server-owned `mmed_ir_catalog_approved_image` policy. Add a newly approved image to that independently qualified policy before it can be saved. A URL and admin assertion alone do not prove reuse rights. Existing build-approved embedded photos are reused only through unchanged legacy product identity; new products with no approved photo use the permitted information treatment. External expert/manufacturer links remain external, escaped links with noopener/noreferrer; no arbitrary HTML/embed.

Amazon/provider volatile fields (title/image/price/rating/reviewCount/availability/offers) are NOT accepted in this admin command schema. Editorial title is explicit MissionMed fallback, not a verified Amazon title. Future authorized provider projection is separately owned, with source, verifiedAt and expiresAt/validity; unavailable/stale fields stay absent. Existing numericAmazonContentEnabled and apiAccessVerified remain false. No scrape, provider credentials or account activation occurs in this package.
