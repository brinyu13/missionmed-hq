**[P1] Main-process alarm does not bound native race worker completion.** The wrapper installs SIGALRM around `qa.execute_native()` at line401, but the accepted harness's `race()` at lines560–564 runs HTTP requests in ThreadPoolExecutor workers and waits for results inside its context manager. An alarm interrupts the main thread; exiting that context waits for worker completion. Worker threads cannot receive the main Python signal. The existing HTTP timeout is a socket-operation timeout, not a complete response/run wall-clock deadline. Thus a delayed in-flight race can outlive the admitted deadline while the harness is still unwinding, and release waits until it finishes. A bounded local reproduction ran the actual native `race()` with two delayed, nonnetwork state fixtures inside actual wrapper run_session: configured deadline0.050seconds, returned/released at0.311seconds, result STOP. The supplied deadline mock raises immediately and misses this behavior. This reproduction did not leave background native work or make a real request; it demonstrates the deadline contract is not enforced for this path. Fix through a separately reviewed bounded transport/worker cancellation or containment contract that preserves identity/history and guarantees no still-running native mutation after lease release. Test a real delayed/racing fixture through the actual harness path, including release only after workers are safely stopped. Simply returning early/releasing while workers continue is not acceptable. A dispatched server request may already have committed; timeout must preserve ambiguity/history rather than assert rollback.
