# Hydration Root Cause

The live gap had two distinct causes:

1. Approved canonical registry intelligence existed in the 6,139-program release, but the Program File and global search projected only a narrow subset. This made populated fields appear absent to students.
2. Existing Parallel, Opus, and Sonnet outputs were distributed across provider-specific artifacts and staging states. After provider-neutral ingestion, every provider-derived claim is still PENDING/REVIEW_REQUIRED. That is an evidence-quality gate, not a source-origin gate, and values must not be exposed as verified facts before review.

The repair projects all approved canonical registry fields live, unifies provider evidence for review, and exposes only pending field names/counts, not pending values. No obsolete provenance rule remains on the live approved-registry projection. No provider fact was fabricated, relabeled, or silently promoted.
