Fixed error copy set (PA-immutable strings; each maps to one truthful state):
- Mic denied (`NotAllowedError`): "Microphone access was not available. You can allow it in your browser settings, or just keep typing."
- Reconnecting (buffered segments): "Connection hiccup. Your recording is safe on this device. Reconnecting…"
- Cannot transcribe now (`transcribe_unavailable`/`transcribe_timeout`): "We can't transcribe right now. Your recording is saved. Keep talking, or try transcription again from review."
- Unable to continue (device/capture failure): "Recording can't continue on this device right now. Everything you said so far is safe. Typing always works."
- Voice unavailable mid-take (rollback/kill): "Voice capture is currently unavailable. Every word so far is kept in your draft. You can keep typing."
- Daily limit reached (HTTP 429, code `voice_daily_limit`, from E1/E2): "You've reached today's recording limit. Everything you captured is saved, and typing is always available. Recording returns tomorrow."
- Length cap stop (20 minutes or the 200-segment bound, same server hard-stop state and same copy): "This recording reached its length limit and was stopped. Everything you said is captured below."

Sweeps: `server/recordings.mjs` interval task started from `app.mjs` boot, guarded by an env `STORYFORGE_SWEEPS=on` default on.

Browser support matrix (binding, from the B1-504A research record URLs): desktop Chrome (webm/opus), desktop Safari (mp4/aac; webm on 18.4+), iPhone Safari (mp4/aac; webm on 18.4+; backgrounding auto-pause), Android Chrome (webm/opus; ~1 min background loss auto-pause). Second-device behavior: recovery of transcript text via the server draft is supported; resuming the MICROPHONE take on a second device is NOT supported and NOT promised (truthful limitation). Closed-laptop recovery: supported to the last uploaded segment + last draft autosave.
