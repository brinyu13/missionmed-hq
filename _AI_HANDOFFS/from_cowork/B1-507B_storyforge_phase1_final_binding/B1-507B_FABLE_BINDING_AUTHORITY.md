## Ruling 2 · FABLE-C1 deletion and audit truth · RULED

BINDING RULING: cross-system atomicity is not claimed; it is replaced by a durable INTENT-FIRST protocol whose truth survives a crash on either side of the R2 boundary. One new additive table IS indispensable: `public.sf_audio_deletion_intents` (exact DDL in the contracts document), FORCE RLS, service-only. The prior delete-first wording is SUPERSEDED.

- State machine, exact: (1) INTEND: one PostgreSQL transaction inserts the intent row (`state='intended'`, object key, category, content-free attribution, run id) and commits. This committed row is the durable evidence that MUST exist before the object is touched and before the next object is processed. (2) DELETE: one R2 DeleteObject call. Success and 404/absent are both acceptable outcomes; timeout/failure leaves the intent `intended` with `attempts+1`. (3) RESOLVE: one PostgreSQL transaction sets the intent to `deleted_confirmed` (or `object_absent`) with `resolved_at` and appends the service audit event in the SAME transaction; if this transaction fails, nothing is recorded and resolution is retried next run WITHOUT harming truth, because the re-issued DELETE returns 404 and resolves as `object_absent`.
- Crash truth: crash before (1) = nothing happened; crash between (1) and (2) or between (2) and (3) = an `intended` row survives, recovery re-issues the idempotent DELETE and resolves; the object is truthfully called deleted ONLY when a resolved intent row plus its audit event exist.
- Retry: `attempts` capped at 3 across runs; exhaustion sets `state='failed'`, appends the audit event, and ABORTS the run with the existing `reconciliation_audit_failed`-class abort so later deletions never proceed past unresolved truth. Already-absent objects resolve as `object_absent` without counting as failures.
- REJECTED: shared/two-phase transactions across R2 and PostgreSQL; audit-after-delete without a durable intent; treating a zero exit code or in-memory state as deletion evidence.
- FULLY RESOLVED: yes.

## Ruling 5 · FABLE-C4 fairness and continuation · RULED

BINDING RULING: one new additive SINGLE-ROW table `public.sf_reconciliation_state` (enforced singleton) holds the durable cursor (`cursor_key`, default empty) and the C5 lease. Ordering is R2 ListObjectsV2 lexicographic key order with `StartAfter = cursor_key`. Advancement, exact: the cursor advances to the last EVALUATED key at each committed 1,000-key page boundary, in the same transaction as that page's intent bookkeeping; abort, suspension, or partial failure leaves the cursor at the last committed boundary so the interrupted page is re-evaluated next run (idempotent: the partial unique index on open intents dedupes); when a run lists fewer keys than a full page before hitting the caps, the cursor RESETS to empty (wrap). Caps unchanged and interacting exactly: <= 5 pages (5,000 keys evaluated) and <= 200 deletes per run; keys beyond the caps are reached by later runs FROM THE CURSOR, which is the starvation fix. `dry_run` advances the cursor identically (the fairness machinery itself must be validated in dry_run; the weekly wrap guarantees full coverage). Bounded-consideration proof: with N total keys, every key is evaluated within ceil(N/5000) runs of its insertion point in key order, and the wrap makes that bound recurring. Restart: the cursor is durable; concurrent runs are excluded by Ruling 6. REJECTED: in-memory cursors, random-start listing, per-prefix round-robin schemes, and any cap increase. FULLY RESOLVED: yes.

## Ruling 6 · PROBE-C5 scheduler coordination · RULED (lease; the replica invariant is NOT sufficient)

BINDING RULING: Railway's one-replica configuration is observable but NOT lockable as a binding invariant (replica count is mutable configuration, and rolling deploys can briefly run two instances), so the single-replica path is REJECTED as the safety mechanism and the smallest lease is authorized on the C4 singleton row. Acquisition: one compare-and-set UPDATE claims the lease when `lease_owner IS NULL OR lease_expires_at < now()`, setting `lease_owner` to the replica's boot-generated id and `lease_expires_at = now() + 30 minutes`. Renewal: every 5 minutes, UPDATE guarded by `WHERE lease_owner = $self`. Expiry/takeover: only after `lease_expires_at` passes, using the SAME database clock (`now()` server-side everywhere; client clocks are never consulted). Ownership re-verification: every page commit and every delete batch is guarded by `WHERE`-clause lease ownership inside its transaction; a lost lease aborts the run with `reconciliation_lease_lost` and writes the run row. Crash: the lease expires on its own; the next scheduler acquires. Release: explicit on clean completion. Topology remains recorded in each run row as evidence, but safety never depends on it. Constants are fixed in code (30/5 minutes); no new environment variables. REJECTED: advisory locks tied to pooled connections (the pool makes session-scoped locks unreliable across transactions), external lock services, and any activation with uncontrolled concurrent schedulers. FULLY RESOLVED: yes.
