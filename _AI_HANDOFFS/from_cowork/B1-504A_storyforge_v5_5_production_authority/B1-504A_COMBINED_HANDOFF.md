## 4. Architecture [RECOMMENDED]

Extension of the existing StoryForge service; no new service, queue platform, or analytics stack.

Recording: segment-scoped MediaRecorder (15 s segments; boundaries at pause and stop; new recorder per segment so every segment is a standalone decodable file; mimeType feature-detected per segment: `audio/webm;codecs=opus`, `audio/mp4`, `audio/webm`, `audio/ogg`). Rationale (evidence-backed): timeslice chunks after the first are not standalone files (W3C mediacapture-record issue 130); Safari <= 18.3 records mp4/aac only while 18.4+ adds webm/opus; segments give durability-by-construction and truthful near-live latency without a realtime PCM pipeline; the adapter's interim/final contract keeps OpenAI Realtime (`gpt-live-transcribe`, WS, PCM16) as a drop-in latency upgrade later without product change.
Segment plan, normative: `segmentPlanMs [4000, 15000]` (4 s opening segment for fast first text, 15 s steady-state, plus pause/stop boundaries); returned by E1 and binding for the latency thresholds.
Transport: segments POST to the StoryForge API (multipart, <= 5 MB each); API stores them in R2 (`storyforge-rec/{studentUuid}/{recordingUuid}/seg-{seq:05d}.{ext}`) and relays to the transcription adapter with `keywords` (medical lexicon + draft-title terms) and `prompt` = previous-segment tail. Client polls session state every 2 s and merges finalized text via the prototype's overlap-merge; ghost line shows in-flight state; draft autosaves after every merge so transcript text is server-durable within seconds (second-device recovery works).
Assembly: on finish, server assembles one playback asset registered through the EXISTING `sf_begin_audio_asset`/`sf_confirm_audio_asset` chain. Option A preferred: ffmpeg concat on Railway (verify feasibility); Option B fallback: ordered-segment manifest with sequential playback. Caps: 50 MB, 20 minutes (countdown from 18), 5 MB/segment, one active session/student, default 60 recording-min/student/day.
Interruption model: auto-pause on `visibilitychange: hidden` and track `mute`/`ended` (iOS backgrounding/lock/calls; Android ~1 min background mic loss); Screen Wake Lock during recording, re-acquired on return; network loss buffers <= 2 segments then auto-pauses honestly; reload recovery from server draft + segments; feature-disable mid-take: grace finish (<= 10 min) on open sessions, immediate refusal of new ones, env kill refuses all; rollback never touches saved content.
Transcript check: chips only from real signals: provider confidence (verify availability [CODEX R-7]) or the versioned repository medical lexicon (fuzzy match, "you decide" copy); nothing auto-corrects; no signals, no chips.
Truthful states [AUTHORITY]: preparing microphone; recording; paused; reconnecting; transcribing; finalizing; ready for review; unable to continue. Typing available throughout. "Live transcription" wording only if measured latency meets thresholds.

## 5. Transcription provider decision

Incumbent disposition: wrap and upgrade. Drills `whisper-1` becomes a bake-off baseline and the wired fallback behind a StoryForge-owned adapter; StoryForge never calls hq code at runtime; StoryForge gets its own scoped `STORYFORGE_OPENAI_API_KEY` [CODEX provision]. Anthropic has no STT product and plays no Phase 1 role; vendors are not forced into one release.

Adapter: `transcribeSegment({buffer, mimeType, keywords, promptTail, languageHint}) -> {text, words?, confidence?, providerId, modelId, latencyMs}` + `capabilities()`; drivers `openai-gpt-transcribe` (recommended primary), `openai-whisper1` (fallback), optional `openai-realtime` (upgrade path); failover primary-to-fallback on hard errors only; no vendor names user-facing; no mocks ever; fail closed truthfully.

Candidates and current official facts (retrieved 2026-07-28 from developers.openai.com and vendor docs): C1 `whisper-1` batch $0.006/min, prompt-only (224-token tail); C2 `gpt-transcribe` batch $0.0045/min with `prompt`+`keywords`+`languages`, accepts webm/m4a/wav (25 MB/request), `stream=true` deltas; C3 `gpt-live-transcribe` Realtime WS $0.017/min, PCM16 24 kHz, interim `.delta`/final `.completed`, `keywords` + `delay` tuning; C4 (benchmark only) Deepgram `nova-3-medical` with Keyterm Prompting: adopting any NEW vendor is a founder gate. OpenAI signs BAAs per its enterprise-privacy page; no compliance claim is made.

Bake-off (binding; one focused day; gates activation, not building): privacy-safe corpus of 40 scripted medical passages (medications incl. enoxaparin, metoprolol, Lasix; procedures incl. Whipple, paracentesis, anastomosis; abbreviations CBC, NSTEMI, PEA, OR, ICU; labs and numbers), accent groups representative of the MissionMed population (South Asian, West African, East Asian, Latin American, Middle Eastern, North American at minimum), conditions (quiet, laptop mic, phone mic via the real capture path, ward-like noise, whisper-quiet), hand-verified references, hashed; three runs per candidate through the real adapter path on the production account; deterministic committed scorer. Cutover thresholds (not weakenable): WER <= 12% and <= C1; medical-term recall >= 92% and >= C1+10; substitution <= 3%; accent degradation <= 8 points; first-text p95 <= 10 s; final p95 <= 8 s; failure < 1% after one retry; cost <= $0.01/min; `BAKEOFF_DECISION_RECORD.md` filed. C2 failing medical thresholds after one keywords enrichment retest escalates to the founder with C4 evidence.

Retention [GATE, recommended launch-safe default]: retain original audio by default; student may delete audio anytime keeping the transcript; story deletion deletes audio; life-of-account retention, account closure deletes objects within 30 days; cohort revocation deletes nothing (recording ability ends, content stays); cancel/abandonment segments hard-deleted (24 h sweep); no legal hold in Phase 1 (flag if a requirement surfaces). Provider-side data handling is part of the privacy design [CODEX]: capture the provider's current official training-use, retention, and ZDR/BAA posture as evidence before cohort activation; a material conflict with the approved policy stops the release. Consent: one-time first-recording inline notice incl. avoid-patient-identifiers reminder; mic requested only on explicit tap. No HIPAA/FERPA or other compliance claims anywhere; privacy-by-design and minimization applied.
Incidents: provider outage degrades truthfully (record-now, transcribe-on-retry); R2 outage buffers then honest auto-pause; credential rotation is isolated by scoped tokens; Cloudflare metrics monthly for storage/egress/cost.
