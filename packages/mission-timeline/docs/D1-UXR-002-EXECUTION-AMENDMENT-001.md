## Self-resolving execution

Engineering issues that preserve the frozen founder-approved product are
implemented, documented, and closed without founder interruption. If an issue
cannot be resolved at that level, the Supervisor isolates only the affected
branch and continues every independent milestone.

Founder interruption remains limited to changes in navigation, workflow,
hierarchy, interaction model, meaningful copy, feature scope, Guided versus
Advanced behavior, theme philosophy, the adaptive timeline algorithm, document
intake behavior, advisor workflow, export workflow, or another visibly
different product experience.

Accessibility tokens, typography tokens, CSS variables, spacing tokens, hover
and disabled states, focus-ring colors, internal aliases, implementation
variables, semantic improvements, and browser-specific implementation details
are engineering-owned when the founder-visible appearance remains materially
unchanged.

## Completion objective and hard boundaries

The run targets all 14 milestones, all 27 binary acceptance criteria, and a
founder-review-ready local candidate. Engineering biases toward shipping the
frozen experience with sufficient direct evidence rather than theoretical
perfection.

`STOP_SAFE` applies only when the Design Freeze is founder-visibly
contradictory, product behavior cannot be determined, a protected system would
be touched, Matrix integration becomes required, or production mutation becomes
required.

Existing local-only, no-touch, no-commit, no-push, no-deploy, no-production, and
no-Matrix constraints remain in force.
